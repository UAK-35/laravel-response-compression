# `.agents/` — the single agentic target

This directory is the **only** place AI tools load **skills**, **custom agents** and **commands**
from. The rules themselves live one level up, in `AGENTS.md`, and every other agentic file in this
repository is a pointer to it.

## Hard rule

**Never load agentic configuration from a parent folder.** This checkout is developed inside a
larger workspace whose root carries its own `AGENTS.md`, `.agents/`, `.claude/` and `.trae/`, all of
them describing a Laravel application. None of it applies here, and `python .agents/verify.py` fails
on any file in this repository that points outside it.

## What lives here

| Path | Purpose | Owned by |
|---|---|---|
| `skills/<name>/SKILL.md` | **the single real skill target** — every tool reads skills from here | generated by `.skills/_sync.py` |
| `skills/<name>/_meta.json` | the generated manifest: name, version, description, tags, `source_hash` | generated |
| `agents/<id>.md` | canonical custom agents | hand-maintained |
| `commands/<name>.md` | canonical command definitions | hand-maintained |
| `toolchain.json` | every command this package runs and the pin on each tool — section 13 of `AGENTS.md` is rendered from it | hand-maintained |
| `machine.local.json.example` | the committed shape of `.agents/machine.local.json`, which is gitignored and holds this machine's paths | hand-maintained |
| `render_local.py` | owns `machine.local.json`: `--init` asks for the paths, `--check` reports unresolved tokens, `--value` answers a token for prose or a shell | hand-maintained |
| `verify.py` | the check: twelve steps in two halves. `tools` **runs programs** — PHP and its version against the pin, the `ext-*` requirements, a coverage driver, composer, Python, PowerShell 7, git, every tool in `bin/tool-paths.php` asked to start through `bin/tool.php`, the hook in this clone, and whether there is a `vendor/` at all. The rest **read files**: this directory against itself, the pointer files, each skill target against its source, the rendered command table, the settings files against their templates, the tokens. `guards` and `gate` run the package's own two path guards and its gate rather than repeating them. Default is everything; `--layer` is the fast subset the hook runs, `--package` is the tools and the two package checks, `--only=STEP` is one reading, `--fix` repairs what a generator owns, `--selftest` plants a fault per step and requires it to be named. A file a person edited is reported, never overwritten | hand-maintained |
| `machine_paths_allowlist.txt` | not present, deliberately: the reading of a machine path belongs to `tests/Unit/Support/MachinePathsTest.php`, which keeps its excuses in the detector beside the reason for each one | — |

## The index — every skill, agent and command

Everything loadable has a row below, and `python .agents/verify.py` (step `index`) **fails** when one
does not: a skill that loads but cannot be found by reading this table can only be found by somebody
who already knew it existed. A row is a markdown table row whose **whole cell** is the name, so a
sentence that mentions a skill is not an entry.

| Skill | Authored in | What it does |
|---|---|---|
| `package-dev` | `.skills/package-dev/` | this package's daily loop — `gate`, `gate-local`, `staged`, `checks-list`, `test`, `test-unit`, `test-types`, `test-lint`, `tidy`, `single-test <path>`, `agentic-check`, `agentic-fix` |
| `package-release` | `.skills/package-release/` | weighing, cutting and pushing a version — `weigh`, `weigh-dry-run`, `release-cut`, `prerelease`, `push`, `unreleased`, `verify-runbooks` |

| Custom agent | Defined in | What it does |
|---|---|---|
| `code-reviewer` | `agents/code-reviewer.md` | reviews a change against *this* package's rules — the semver promise, the read-once config, the guards, the docs records — rather than against generic Laravel advice |

| Command | Defined in | What it does |
|---|---|---|
| `gate` | `commands/gate.md` | run the package's gate and report what each of the nine checks said |
| `release` | `commands/release.md` | weigh the tree, and cut a version only when asked for one |

## Where the source is

Skills are **authored** in `.skills/<name>/` (`skill.yaml` + `instructions.md`) and generated into
`.agents/skills/<name>/`. Edit the source, then:

```bash
python .skills/_sync.py      # regenerate the skill targets, the GEMINI.md imports, the Windsurf pointers
python .agents/verify.py     # prove the layer is consistent
```

## How each tool loads from here

| Tool | How it reads `.agents/` |
|---|---|
| Freebuff / Codebuff | loads `.agents/skills/<name>/SKILL.md` and `.agents/agents/<id>.md` natively |
| Claude Code | documented to read `.agents/skills/` directly — `CLAUDE.md` points here |
| Trae | `.trae/settings.json` → `skillRoots` / `agentRoots` = `.agents/…` |
| Gemini CLI | `GEMINI.md`'s generated `<!-- SKILLS-IMPORT -->` block `@`-imports each `SKILL.md` |
| Windsurf | `.windsurf/rules/<name>.windsurf.md` pointer rules (generated) |
| Cursor, Continue, Junie, Kiro, Copilot | a pointer file each, naming `AGENTS.md` and this directory |

A pointer never restates a skill or an agent, so it cannot drift. There is deliberately no
`.claude/skills/`, `.codex/skills/`, `.windsurf/skills/`, `.trae/skills/` or `.gemini/skills/`.

## The two checks worth knowing

- **`verify.py` asks the tools rather than describing them.** The `tools` step runs the interpreter,
  the manager, the four dev tools through `bin/tool.php`, and the version probes its pins came from;
  the other steps read the files here. A `vendor/` that is missing is reported as a note with the one
  command that fixes it, because a green run that silently asked nothing is the failure the step
  exists to prevent.
- **It does not re-implement the package's guards.** A machine path is read by
  `tests/Unit/Support/MachinePathsTest.php` and a climb out of the repository by
  `RepoEscapesTest.php`, both of which own that reading, its excuses, and the tests that prove they
  fire. A second implementation here would be a guard of its own — which is exactly what
  `docs/guards.md` refuses — so the step named `guards` runs those two tests instead.
- **The package's gate is `composer checks`, not this.** The `gate` step runs
  `composer checks -- --require-all`, and `composer test:unit` remains its own command because the
  gate deliberately measures no coverage. Nothing in this directory replaces either.
